# 中文证明的权威写作规范

本页说明首版 corpus 格式。本轮全篇整合使用[执行契约](full-paper-integration-20260930.md)、[可读证明规范](proof-writing-standard.md)与[文字到 Lean 对照](human-to-lean.md)，新内容位于 `research/full-proof-integration-20260930/`。此前 v2 内容是历史示例。不要分别改动生成的 Markdown 与其权威 JSON。

proof.zh.md 是中文讲解的权威位置，网页从它读取。默认面向本科高年级数学基础的相关研究生。原论文来源、原编号和术语保留；公共 API 按数学概念命名。

每份证明写明完整命题、对象和全部假设；随后给出关键思路、分步推导、空集/零值/分母等边界，以及原文对应和采用的公共引理。一步只承担一个可审查的数学动作，注明等式/不等式所用依据。长计算可展开，不能以“显然”替代关键前提。

公式使用 $…$ 或 $$…$$，展示层的 KaTeX 不支持所有 TeX 宏；保留可读标准命令与原始源码。Lean 代码不手工复制成独立“准确签名”；从 catalog 及关联源码读取。

为关键步骤在正文单独一行写入 `<a id="step-1"></a>`、`<a id="step-2"></a>` 等标记；编号必须为正整数。metadata.steps 使用相同的稳定 ID，并关联实际 catalog 中的完全限定 Lean 声明。网页只将这种严格标记转换为内部锚点，其余 HTML 一律转义；代码块中的标记保留为代码。显式 ID 重复时只保留第一个锚点；段落自动 ID 使用另外的名称，避免抢占步骤 ID。没有显式标记的旧正文仍有自动段落锚点，但新证明应使用显式 ID。

侧栏的步骤链接可进入实际 API 签名；本地视图还可跳到声明源码，API 页可以返回对应中文步骤。缺失锚点或目录声明明确显示未关联，不生成错误链接。多个数学步骤可以解释同一个完整 Lean 声明，这不表示每一步都存在独立声明或已分别验证。仅用于类型转换的辅助声明须说明其角色。

下列仅是写作结构，不是已完成论文证明：

~~~markdown
# 命题与假设
对象、定义域、量词、参数限制及结论。

# 思路
说明关键消去、反演或组合机制。

# 第一步：展开定义
<a id="step-1"></a>

列出所用定义，说明求和是有限和。

# 第二步：使用公共引理
<a id="step-2"></a>

链接声明名，逐项确认其前提。

# 边界与原文对应
核对空集、基线、页码、原编号和符号映射。
~~~

相应元数据结构如下；实际保存时使用已经存在且与步骤对应的声明，不能保留占位名称：

~~~yaml
steps:
  - id: step-1
    title: 展开定义
    lean_declarations: [实际的完全限定声明名]
  - id: step-2
    title: 使用公共引理
    lean_declarations: [实际的完全限定声明名]
~~~

若重写暴露原文错误，按 review.md 登记原式、位置和证据。当前三篇已授权直接修复证明，必须保持原命题及其假设；原命题错误时单列反例，不以改命题代替完成证明。其他材料按已有授权处理，未受影响条目继续。
