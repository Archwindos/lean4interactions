# 可读证明与可验证边界

这份规范用于论文结果重写与公共证明。`math-content.json` 是本轮网页和 agent package 的共同数学输入，独立中文 Markdown 由同一输入生成。原 PDF 保留不变；每篇正式来源单独记录版本、文件哈希和从 1 开始的 PDF 页码。

每条结果先给精确命题、对象、定义域与量词。模型输出写成 \(v(x_S)\)，其中 \(x_S\) 是固定样本与输入基线产生的掩码输入。公共集合函数记为 \(g(S)=v(x_S)\)，去基线函数记为 \(g_0(S)=v(x_S)-v(x_\varnothing)\)。\(g_0(\varnothing)=0\) 是定义的后果，不能写成原始模型输出 \(v(x_\varnothing)=0\)。输入基线向量与输出基线标量也须分开。

证明按自然的数学结构组织：必要定义、短思路、需要的辅助引理及其证明、主证明、空集边界与一个小例子。标题对应实质动作；一个辅助引理可包含数段推导，不把每句拆成一张卡片。正文用标准 TeX 排版核心记号，程序类型、命令、内部变量名和源码定位放到 Lean 对照层。

有限求和的改写须说明索引族如何分组或一一对应。符号变化须给出基数与指数的依据；用归纳时须写出归纳假设的量词，尤其当插入步骤把原函数换成差分函数时，说明为什么假设必须对任意函数成立。调用已有结论前逐项检查其前提。不能用“显然”“由唯一性”替代所需引理的完整理由。

每个证明必须明确空集是否参与求和。对重构有 \(I_g(\varnothing)=g(\varnothing)\)；对唯一性必须使用同一组系数在全部掩码上成立的条件，包含空集。若删去空集项，则在和外加回输出基线。小例子至少核对完整输入与一个边界输入，不能只让最终总和碰巧相等。

公共证明与论文适配分开存储。复用的完整证明只在 `shared_proofs` 存一份；论文页在说明自己的定义与约定后，直接展示所复用的完整证明。来源为已有结果时，明确标注继承与本篇重证；项目库页面不得冒充一篇新论文或新论文定理。

`original_statement_md` 和 `original_proof_md` 的内容类型须写清。本轮全篇整合要求完整原陈述和原证明的数学转录，并附正式 PDF 页码；摘录、项目译文和重写须另标，不得将摘要称为全文。此前 v2 的公式摘录只能作为历史输入，不能自动继承为本轮完整原文。

数学正文步骤、形式定义、实际声明与源码行分别有稳定标识。一个人类证明的多个步骤可以解释同一条公共声明内部的证明；这不等于新建了同样数量的 Lean 定理。对照须区分整条定理复用、既有证明内部细节、论文语义对齐与尚未形式化的内容，链接必须来自真实源码和真实审计报告。

结果状态分开记录：`rewrite_status` 使用 `complete/not_started/in_progress`；范围另放 `completion_scope`；代理对齐为 `agent_checked_selected_statement`，用户审核另为 `pending`。编译与公理审计通过不能替代原文语义对齐，也不能关闭原文数学问题。选定子结论完成不代表整篇论文或母定理完成。

发现具体疑点时，登记正式页码、原式、反例/推导依据与影响范围。数学问题、记号待核对与抽取错误分别分类。当前三篇已获证明修正授权：直接补全或替换错误证明，标出原错处，原命题及其假设保持不变；命题错误另列。其他材料按[审校规则](review.md)中的已有授权处理。用户确认与技术判断仍分别记录，普通项目文字、类型或构建错误可直接修复。
