# 下游 API 试用

试用目的是检验新使用者能否只根据库文档、catalog 和源码找到并组合引理。它与维护者编写的 consumer 示例不同。已提供答案的示例可以验证运行方式，不能单独宣称完成“未参与编写者”的独立试用。

准备：读取 library-quickstart 与 ai-use-library，确认固定版本、准确签名和实际报告。建立项目内独立下游包，仅依赖 HarsanyiLib；使用者不需要 archive。

推荐尚未给出具体解法的任务：

1. 对任意集合函数 v 和非空有限集合 S，证明 v 中心化后的 S 交互与原函数相同；随后推导任意两个集合函数之差的对应结论。先检索而不预先指定引理。
2. 用户要求“任意 v 在空集上的 interaction 等于 0”。使用者须检查库定义，指出缺少的条件并给出可复核反例。若此目标来自论文，按 review.md 登记问题，等待用户确认与独立修正授权；不能自行把目标改写后称原目标已证明。

执行记录至少包含：试用者是否参与 API 编写、任务原文、库/Lean/mathlib 版本、检索词与命中、假设差异、使用的准确声明、下游源码、真实命令/报告、失败与最终结果。另存任务与答案，避免把给定答案当独立探索。

当前执行状态：2026-09-30，未参与库实现的 `gpt-6.1-sol / max` 代理已完成一次独立试用。它先根据文档和 catalog 检索，在现有 consumer 的锁定依赖环境中编译独立源码，完成包含空集分支的去基线仿射交互公式及重构唯一性，组合六条公共引理；另验证缺少非空前提的调用会被 Lean 拒绝，并证明空集反例。详细过程见 [独立试用记录](reviews/api-playtest.md)，机器证据见 [report.json](../reports/api-playtest/20260930-max-centered-affine/report.json)。该试用使用独立源码及独立审计，没有修改公共库；新增文件不由旧三包报告覆盖。之后可继续安排新的使用者和任务，记录实际发现的问题与结果。
