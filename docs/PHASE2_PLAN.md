符号基准为 `g(S)=v(x_S)`、`b=g(∅)=v(x_∅)`、`g₀(S)=g(S)-b`。模型输出不默认零基线。固定输入游戏与总体条件熵分别命名；AND/OR 分量、再次掩码后的游戏、输入相关归一化系数分别标明。空间 Fourier 频率与样本/损失景观频率保持各自定义域。原文中的记号和错误公式不随规范重写而覆盖。

共享关系需要数学对齐。Möbius 重构、中心化、Shapley 系数、有限求和和 Gaussian 矩等优先检查；仅仅相似或使用同一辅助引理的结果保存依赖关系。条件不一致的版本分别保留。原命题错误继续单列，修正证明的授权不允许改变原假设或结论。

## 实施顺序与人员

1. 固定第一轮快照，读取根问题台账和两个数学交接文件，先形成逐条修改清单。
2. 两名数学代理各负责六篇，检查全部重写正文、前提、符号、中英文及共享应用。根裁定跨论文的精确合并关系。
3. 整合代理根据确认的映射更新全局符号、共享引用和界面；将文字/数学变化与界面变化分开保存，方便复核。
4. 根核对原文保全、数学语义和实际阅读流程，保存变更及验收报告。
5. 根据 GitHub 配置讨论的结果决定提交和发布方式，并记录实际本地与远端提交；未推送成功时不写“已发布”。

根按 high 强度推进，实施代理使用 **gpt-6.1-sol / high**。采用两名数学代理、一名整合代理；任务只传递必要文件和验收条件，复用现有报告，避免重复读取长会话。

数学分工延续现有工作单：一组为原三篇 Sparse/Generalizable 与 F01/F04/F06；另一组为 HarsanyiNet/Layerwise/Coalition 与 F07/F08/F10。整合代理拥有全局数据、翻译兼容层、界面、API 与软件检查。新代理启动时由根明确交接文件所有权，避免覆盖并行修改。

## 必要检查与停止条件

- 全部原文、正式来源、稳定论文/结果 ID 和目标映射保全。已确认的项目说明误放作者字段等问题，单独记录迁移依据和历史内容。
- 所有重写字段及中英文公式逐条对齐；没有证明目标因“难处理”改为非目标。
- 共享正文到论文定义转换、具体应用和实际 Lean 声明形成可追溯关系。
- Lean 源码变化时，重跑受影响模块、适配与公理审计；只有人读记号变化时，复用新鲜的机器证据并重新核对人读语义。
- 对实际数据/UI 变化运行必要的公式、双语、API、浏览器及回归检查。全库规范字段普遍变化时做一次完整检查；局部修复按影响范围复测。
- 实测查论文、查定理、读长证明、比较原文错误、查看 Lean 后返回、查符号后返回等流程。性能改善以相同任务比较，保留全部信息。
- 提交前再次审核实际工作树和实际 Git 暂存区；私稿、派生材料、环境、凭据及本机上传脚本继续排除。

出现来源缺漏、前提变化、机器报告过期、翻译改变公式含义或私稿泄漏风险时停止相应发布步骤，记录问题并修复；已有无关通过证据继续保留。
