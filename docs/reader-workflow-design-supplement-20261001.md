# 第二阶段阅读设计补充：十篇实测后的约束

本文件补充 [阅读流程评估](reader-workflow-evaluation-20261001.md)，只记录设计与验收要求。第一轮仍使用现有布局；实施须等根代理明确通知阶段切换。十篇中间软件验收及其输入哈希保持在原报告中，不因本补充改写成十二篇验收。

## 符号详情按需渲染

[十篇性能记录](../reader/evidence/twelve-paper-20261001/ten-paper-reading-performance.json)绑定公开数据 SHA-256 `b32f2c9d9bbfb9a8212f3fc52c5984f46d548abdc344ae98c607ebbea2d85937` 和当时的界面。符号页构造 58,765 个 DOM 节点，五次本地导航中位数 1,042.18 ms；长证明为 6,302 个节点、246.78 ms。公开 JSON 为 10,517,031 字节。这些是同一机器、同一 Chromium 的本地冷读与缓存读混合测量，不能推断远程网络或较慢设备的耗时。

第二阶段优先在打开符号卡片时生成详细映射和公式。搜索仍遍历完整符号数据，匹配域、作用域、基线、作者符号、冲突说明与全部论文映射；未展开不表示未收录。深链接须定位并展开目标卡片及其论文映射，读者返回时恢复语言和原证明步骤。按需渲染只延后节点和公式生成，不能删字段或仅搜索当前可见卡片。

同一符号在阅读页就地查看时，显示当前论文的定义、域、作用域和基线，再给全表入口。全表保留论文筛选、所有映射和稳定符号 ID。验收用实际深链接、未展开卡片中的检索词、跨论文映射、键盘展开及长证明往返检查这些能力；同时重测十二篇符号页，比较相同任务和节点数量。不能用删除说明或隐藏问题卡减少页面高度来声称性能改善。

## 原命题、当前结果与机器范围分别表达

默认阅读顺序为结论、当前条目的条件和局部符号、该论文完整逻辑、机器证据入口。结论区同时回答三个独立问题：作者原命题是否成立；本页给出的是同一命题的证明、原子句反例、条件性子结果还是范围分析；实际 Lean 证据证明了哪一段。原命题判断和机器证据角色是独立维度。

例如，已完成的机器子句反例可以属于仅部分被反驳的复合原命题；有人读反例的条目也可能只有部分组件已形式化。不能按声明名称或原命题判断推断机器角色。F10 的正确辅助公式不得以同一标题静默替代作者错误的 Proposition 1；作者原式、错误影响和当前有效子结果要有清楚归属。所有真实条件先于推导可读，显著数学问题留在主阅读路径。

共享证明保留独立稳定入口和当前论文实际使用的前提，正文只出现一次。低频的来源、导出、JSON、代码和报告收纳到对应材料区域；原陈述、作者证明和正式原页仍能从同一原文对照入口到达。返回阅读位置、语言和步骤是同一任务的组成部分，不能以新的导航起点代替。

F06 开发包的四份共享证明直接复制论文完整步骤，只改步骤 ID；现有 `stepIdentity` 又包含 ID，因此相同正文会再次整段出现。第二阶段须由数学作者把论文步骤写为实际适配、引用和前提核销，公共证明保持一份权威正文，并用稳定引用指向它。界面按真实依赖显示论文逻辑与公共入口，不能仅用文本去重隐藏两份仍被当成独立证明的数据；第一阶段不改这些数学字段。

Lean 面板的首屏优先使用当前源码中的实际定理声明或简洁签名，并显示当前文字步骤所使用的前提、结论与对应源码。完整展开核验类型及公理依赖保留在可展开区域。`Eq.{1}`、`HMul.hMul` 和大量 universe 参数属于真实核验数据；不能靠字符串替换改写它们以制造简洁机器类型。简洁入口应来自已核验的源码/header 与步骤映射，并保持到原始报告的追溯链。先检查现有面板和 API 已具备的能力，再实施实际缺少的呈现，避免重复造接口。

第二阶段验收继续使用长证明、错误命题、公共证明和符号映射四条实际任务，另选一条 F10 原命题与有效子结果并存的路径及一条只有部分机器组件的路径。逐项核对条件归属、问题可发现性、原文版本差异、机器范围、来源可达性和阅读位置，再报告性能变化；按钮数量本身不是改善证据。

## 第二阶段的保全边界

第一轮继续逐字段保全旧六篇基线。第二轮规范重写允许经审查改变重写字节，验收转为：正式原件及真实作者原文可追溯，稳定结果 ID 与数学目标没有丢失，全部变更在明确允许的字段/条目清单内。保存第一轮快照和原报告，逐项记录修改前后值、理由、来源及影响；不能把第二轮的预期改写当作第一轮保全失败，也不能用“符号整理”隐藏目标或范围变化。

`f11-matching-metric` 的旧作者字段混入了项目中文注。第二轮须对照正式 PDF21 Appendix M，把项目说明移出作者原文，保留旧字段与来源依据，并登记这是源边界纠正的例外；不能声称该作者字段仍字节一致。规范式采用明确的 matching ratio 名称、`g(S)=v(x_S)` 与基线，AND/OR 索引不因集合相同而合并，分母为零时不补造一个值。数学代理完成来源与范围核对后才更新数据。

AI 使用文档的人读游戏示例也纳入同一符号审查。抽象集合游戏使用 `g` 和中心化的 `g`，模型输出使用 `v(x_S)`；真实 Lean 声明中名为 `v` 的 `Game` 参数及其类型保留并解释，不因人读规范而重命名已验证代码。图像、频谱、卷积权重等不同域的记号按实际作用域保留，不能把所有 `v`、`b` 或 `g` 全局替换为同一概念。
