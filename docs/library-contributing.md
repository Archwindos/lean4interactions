# 扩展 HarsanyiLib

先读取 library-api、math-conventions 和 formalization。公共库只依赖 mathlib；论文或用户目标在下游组合调用。已有引理足够时，不复制其证明到公共模块。

新增引理须有复用价值、完整假设、准确 Lean 签名、中文说明和可编译示例。先搜索本库与 mathlib，记录不足；不为一个新目标静默修改已有声明的假设或结论。定义转换需说明方向、前提和性质保持。私稿特有证明默认 private，不自动纳入公开模块。

变更步骤：

1. 在正确概念模块完成源码，避免全局临时公理和占位证明。
2. 用独立下游项目调用新引理，完成一个组合结论；不能只以 import 或 #check 验收。
3. 按实际生成脚本更新 catalog、中文说明、来源和 proof 元数据；精确签名从环境提取。
4. 执行 scripts/verify-lean.sh，检查真实构建及传递公理。允许的公理默认为 propext、Classical.choice、Quot.sound；不得含 sorryAx。
5. 执行 scripts/archive impact <id>，重验受影响的应用与示例；执行 validate 和网页链接检查。

实质接口变化需写版本变更、影响清单和迁移方法。兼容别名必须满足数学等价，不能掩盖新增条件。源码/工具链/依赖变化后旧验证过期，重新生成报告。

发现原论文数学错误先按 review.md 登记；确认问题和授权修正独立。已授权的修正结果单独登记，不替换原文，也不计作原命题完成。
